# Smart Wardrobe 발표 제작 기준

이 문서는 Smart Wardrobe 8분 발표 웹 덱의 방향과 제작 규칙을 정리한 기준 문서다.

## 1. 발표 목표

- 발표 시간은 8분 이내로 맞춘다.
- 첫 장에는 반드시 기억에 남는 훅을 둔다.
- 기능을 나열하기보다 문제 → 해결 방식 → 실제 동작 → 검증 순서로 보여준다.
- 발표 웹 주소 하나만 전달해도 실행되도록 만든다.
- 발표 전 인터넷, 브라우저, 화면 비율, iframe, CDN 의존성을 점검한다.

## 2. 시각 방향

- 기본 모드는 밝은 모드로 한다.
- 전체 배경은 밝은 블루·아이스 블루 계열로 통일한다.
- 초록색 중심의 네온 테마와 지나치게 어두운 배경은 사용하지 않는다.
- 본문은 Pretendard 또는 Noto Sans KR을 우선 사용한다.
- 한국어 본문은 발표 화면에서 읽을 수 있도록 크게 설정한다.
- 16:9 비율을 기준으로 설계한다.
- 장식보다 가독성, 계층, 여백을 우선한다.
- 슬라이드마다 핵심 문장은 하나만 둔다.

## 3. 첫 장 방향

- 첫 장의 제목은 `스마트 옷장.`을 사용한다.
- 제목 아래 훅은 `찾고 싶은 옷이, 먼저 빛난다.`를 사용한다.
- 옷걸이 전체가 계속 회전하는 연출은 사용하지 않는다.
- 옷걸이는 실제 제품처럼 고정된 삼각형 실루엣으로 보여준다.
- 내부에는 문서에 정의된 부품만 단순하게 보여준다.

## 4. 하드웨어 모델 기준

문서에 정의된 핵심 부품만 표현한다.

- `PN532 NFC RFID Card Sensor Module`
- `Red PCB V3-style PN532`
- `XIAO ESP32-C6`
- 상태 LED 및 330 Ω 저항
- 100 µF 16 V 커패시터
- +5 V pogo pin 2개
- GND 접점 및 금속 Hook
- 자석

세부 규칙:

- PN532는 사용자가 제공한 파란 PCB 레퍼런스처럼 표현한다.
- PN532를 카메라 렌즈처럼 과도하게 분해하거나 잡다한 광학 부품을 추가하지 않는다.
- pogo pin은 PCB 아래가 아니라 옷걸이 고리/고리 목 부분의 전원 접점으로 표현한다.
- 실제 3D 모델, CAD, 보드 사진이 확보되면 코드로 만든 임의 모델보다 실제 에셋을 우선한다.
- Three.js 모델 파일은 `/assets/models/`에 둔다.

## 5. 라이브 시연

라이브 시연은 반드시 두 화면을 동시에 보여준다.

- 왼쪽: 스마트폰 중계 화면
- 오른쪽: 직접 만든 데스크톱 앱
- 두 화면 모두 iframe으로 연결할 수 있어야 한다.
- 현재 레이아웃 비율은 왼쪽 중계 화면을 크게, 오른쪽 앱을 작게 둔다.
- 기본 비율은 왼쪽 `1.28fr`, 오른쪽 `0.72fr`로 한다.
- 앱이 완성되기 전에는 해당 위치에 연결 가능한 placeholder를 둔다.
- 앱 URL과 모바일 URL만 바꾸면 바로 시연할 수 있게 한다.

권장 시연 흐름:

```text
스마트폰에서 옷 선택
→ 서버/앱 상태 변경
→ 해당 옷걸이 LED 점등
→ 스마트폰과 데스크톱 화면 동시 갱신
```

## 6. 애니메이션 도구 사용

- GSAP는 텍스트, 슬라이드 진입, 화면 전환에 사용한다.
- anime.js는 3D 모델 등장, PN532 보드 등장, LED 펄스, 라벨 순차 등장, 블루 조명 호흡에 적극적으로 사용한다.
- 애니메이션은 계속 회전시키기보다 등장·반응·상태 변화에 집중한다.
- 애니메이션이 없어도 핵심 내용이 읽히도록 만든다.
- `prefers-reduced-motion` 환경에서는 애니메이션을 줄인다.

## 7. 발표 덱 구조

```text
presentation/
├─ index.html
├─ styles.css
├─ slides.js
├─ slides/
│  ├─ 01-opening.html
│  ├─ 02-problem.html
│  ├─ 03-solution.html
│  ├─ 04-hardware.html
│  ├─ 05-live.html
│  ├─ 06-proof.html
│  └─ 07-close.html
├─ assets/
│  ├─ models/
│  ├─ images/
│  └─ videos/
└─ tests/
```

- `index.html`: 발표 진입점과 iframe 컨테이너
- `styles.css`: 공통 폰트, 색상, 간격, 컨트롤
- `slides.js`: 슬라이드 목록, 이동, 해시, 전체화면, 자동 진행
- `slides/*.html`: 각 슬라이드의 독립 화면
- `assets/models/`: 실제 GLB/GLTF 모델
- `tests/`: 슬라이드 구조 및 기능 smoke test

## 8. 제작 순서

각 슬라이드를 먼저 독립적으로 설계하고 검증한 뒤 통합한다.

1. 슬라이드의 목적과 핵심 문장을 정한다.
2. 필요한 기능과 에셋을 먼저 설계한다.
3. HTML/CSS/JavaScript로 슬라이드를 독립 구현한다.
4. 슬라이드별 기능 테스트와 시각 점검을 한다.
5. 마음에 들지 않으면 통합 전에 해당 슬라이드만 수정한다.
6. 승인된 슬라이드만 발표 덱에 합친다.
7. 마지막에 8분 타이밍, 전체화면, iframe, 네트워크 환경을 통합 테스트한다.

## 9. 테스트 기준

### 기능 테스트

- 이전/다음 버튼
- 방향키와 PageUp/PageDown
- Home/End 이동
- 해시 URL 이동
- 전체화면
- 자동 진행
- iframe URL 연결

### 라이브 통합 테스트

- 스마트폰 iframe 표시
- 데스크톱 앱 iframe 표시
- 앱 URL 미입력 시 placeholder 표시
- 모바일 URL 미입력 시 placeholder 표시
- 이벤트가 두 화면에 반영되는지 확인

### 시각 테스트

- 16:9에서 글자 잘림 없음
- 밝은 블루 배경 유지
- 흰색 글자가 밝은 배경에서 묻히지 않음
- 모델과 라벨이 겹치지 않음
- 애니메이션이 발표 내용을 가리지 않음
- 발표자 노트 없이도 흐름이 이해됨

## 10. 데이터와 표현 원칙

- 차트가 필요하면 Chart.js를 사용한다.
- 차트와 수치에는 사용자가 제공한 값만 사용한다.
- 실제 측정하지 않은 성능 수치는 임의로 만들지 않는다.
- 실물 검증 전 항목은 `REQUIRES_PHYSICAL_TEST`로 구분한다.
- 실제 하드웨어 사진, 시리얼 로그, 앱 상태 변화가 있으면 장식용 3D보다 우선한다.

## 11. 발표 품질 우선순위

모든 슬라이드를 과하게 꾸미지 않는다. 완성도의 대부분은 다음 두 장면에 집중한다.

1. 첫 장의 실제 제품 같은 스마트 옷걸이 소개
2. 스마트폰 → 데스크톱 앱 → 옷걸이 LED로 이어지는 라이브 시연

나머지 슬라이드는 문제, 구조, 검증을 명확하게 뒷받침하는 역할로 둔다.
