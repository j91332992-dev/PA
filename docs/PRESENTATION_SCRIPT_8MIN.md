“첫 번째 문제입니다.”

“계절이 지나거나 옷장에 여러 종류의 옷이 섞여 있으면, 원하는 옷이 분명히 옷장 안에 있어도 정확한 위치를 찾기 어렵습니다.”

“특히 셔츠나 티셔츠처럼 비슷한 색과 형태의 옷이 많을수록, 옷을 하나씩 꺼내 확인해야 합니다.”

“결국 사용자는 옷을 찾기 위해 기억에 의존하게 되고, 기억이 정확하지 않으면 옷장을 계속 뒤지게 됩니다.”

“이 문제의 핵심은 옷이 사라진 것이 아닙니다. 시스템에 옷의 위치 정보가 없다는 것입니다.”

## 9. 고객 분석 — 가장 먼저 누구의 문제를 해결할 것인가

### 화면

세 고객군을 세 카드로 나누어 보여준다.

1. 옷이 많은 가정
2. 소형 옷가게·쇼룸·의상실
3. 1인 가구

가운데 또는 하단에는 `1차 타깃: 옷이 많은 가정`을 강조한다.

### 대본

“저희의 고객은 크게 세 가지 집단으로 세분화했습니다.”

“첫 번째는 옷이 많은 가정입니다. 가족 구성원이 여러 명이거나 계절별 옷을 많이 보관하는 집에서는 옷의 수가 늘어날수록 위치를 기억하기 어렵고, 원하는 옷을 찾는 시간도 길어집니다.”

“두 번째는 소형 옷가게, 쇼룸, 의상실입니다. 이곳에서는 개인의 옷장을 관리하는 것을 넘어, 샘플이나 재고가 어디에 있는지 빠르게 찾는 것이 중요합니다.”

“세 번째는 1인 가구입니다. 공간은 제한되어 있지만 옷과 물건을 효율적으로 관리하고 싶어 하는 사용자입니다. 특히 바쁜 생활 속에서 정리와 탐색에 쓰는 시간을 줄이고 싶다는 니즈가 있습니다.”

“이 세 집단 중 저희의 1차 고객은 옷이 많은 가정입니다.”

“이유는 문제의 강도가 가장 높고, 하나의 옷장 안에서 바로 사용성을 검증할 수 있기 때문입니다. 옷이 많을수록 ‘무슨 옷이 있는지’, ‘그 옷이 어디 있는지’, ‘지금 바로 찾을 수 있는지’에 대한 요구가 분명해집니다.”

“저희는 이 고객의 니즈를 네 가지 기능으로 연결했습니다.”

“무슨 옷이 있는지 모를 때는 앱의 옷 목록으로 확인합니다. 옷이 어디 있는지 모를 때는 NFC UID와 옷걸이 위치를 연결합니다. 찾는 시간이 길어질 때는 앱의 Find 기능으로 해당 옷걸이의 LED를 켭니다. 그리고 매번 사용자가 위치를 직접 입력하지 않아도 되도록 태그 인식과 상태 업데이트를 자동화합니다.”

“즉, 고객이 원하는 것은 복잡한 장치가 아니라, ‘내 옷이 무엇이고 어디 있는지 빠르게 알고 싶다’는 단순하고 명확한 경험입니다. 이제 이 니즈를 실제 시스템으로 어떻게 충족하는지 보여드리겠습니다.”

## 11. 어떻게 기억하고, 어떻게 옷을 찾는가

### 화면

```text
NTAG213
  ↓
PN532 NFC 리더기
  ↓ I²C
XIAO ESP32-C6 옷걸이
  ↓ ESP-NOW
XIAO ESP32-S3 Gateway
  ↓ Wi-Fi
Backend / Database
  ↓ WebSocket
Web / PWA
```

### 대본

“그럼 시스템이 어떤 방식으로 옷을 기억하는지 순서대로 설명드리겠습니다.”

“먼저 옷에 부착된 NTAG213은 옷을 구분할 수 있는 고유 UID를 가지고 있습니다.”

“옷걸이에 들어 있는 PN532 NFC 리더기가 이 UID를 읽습니다. PN532는 태그를 찾고 UID를 읽는 역할을 합니다.”

“읽은 정보는 I²C 통신을 통해 XIAO ESP32-C6로 전달됩니다. C6는 옷걸이의 메인 컨트롤러로, NFC 데이터를 처리하고 옷걸이의 상태를 판단합니다.”

“그다음 C6는 ESP-NOW를 통해 XIAO ESP32-S3 Gateway로 상태를 보냅니다. Gateway는 Wi-Fi를 통해 서버에 전달하고, 서버는 데이터베이스에 옷과 옷걸이의 상태를 기록합니다.”

“웹 앱은 WebSocket을 통해 이 상태를 실시간으로 받습니다. 그래서 사용자는 옷걸이를 직접 확인하지 않고도 스마트폰이나 웹 화면에서 옷의 상태를 볼 수 있습니다.”

“반대로 사용자가 앱에서 ‘찾기’를 누르면 명령이 서버에서 Gateway, ESP-NOW, C6 순서로 내려갑니다. 마지막에는 해당 옷걸이의 LED가 켜지고, 장치는 ACK를 반환합니다.”

“정리하면, 옷을 찾는 방향은 단순합니다.”

“태그를 읽고, 위치를 기록하고, 사용자가 찾기를 누르면 해당 옷걸이가 직접 알려주는 구조입니다.”

## 12. 앱 사용 방법

### 화면

앱의 옷 등록 화면 → 옷 목록 → 찾기 버튼 순서로 보여준다.

### 대본

“앱 사용 방법도 간단합니다.”

“처음에는 옷 추가 화면에서 옷의 사진과 이름, 카테고리를 입력하고 NFC UID를 등록합니다.”

“등록이 끝나면 앱에는 사용자의 옷 목록이 만들어집니다.”

“사용자가 옷을 찾고 싶을 때는 목록에서 해당 옷을 선택하고 ‘찾기’를 누르면 됩니다.”

“앱은 해당 옷이 연결된 옷걸이를 특정하고, 그 옷걸이에만 찾기 명령을 보냅니다. 사용자는 옷장을 처음부터 다시 뒤질 필요 없이, 켜진 LED를 따라가면 됩니다.”

## 13. 라이브 시연

### 화면

- 왼쪽: 스마트폰 중계 화면
- 오른쪽: 직접 만든 데스크톱 앱
- 화면 아래: 이벤트 흐름 또는 상태 표시

### 대본

“이제 실제 사용 흐름을 라이브로 보여드리겠습니다.”

“지금 왼쪽 화면은 사용자가 보는 스마트폰 중계 화면이고, 오른쪽 화면은 저희가 직접 만든 데스크톱 앱입니다.”

“먼저 앱에서 `[시연할 옷 이름]`을 선택하겠습니다.”

`[앱에서 옷 선택]`

“그리고 ‘찾기’ 버튼을 누르겠습니다.”

`[찾기 버튼 클릭]`

“지금 명령이 생성되고, Gateway로 전달되고, 옷걸이로 내려가는 과정이 화면에 표시됩니다.”

`[이벤트 로그 또는 상태 변화 표시]`

“이제 해당 옷걸이의 LED가 켜집니다.”

`[실제 LED 또는 영상 확인]`

“중요한 점은 모든 옷걸이의 LED가 켜지는 것이 아니라, 선택한 옷이 연결된 옷걸이만 반응한다는 점입니다.”

“그리고 장치가 명령을 받았다는 ACK까지 반환되기 때문에, 앱에서는 단순히 명령을 보낸 상태와 실제 옷걸이가 반응한 상태를 구분할 수 있습니다.”

“이 흐름을 사용자의 관점에서 다시 말하면, 옷장 앞에서 옷을 하나씩 꺼내 확인하는 대신 스마트폰에서 옷을 선택하고, 빛나는 옷걸이를 따라가면 되는 것입니다.”

> 라이브가 불안정할 때의 백업 멘트:
>
> “현장 네트워크 상태에 따라 실제 장치 연결이 지연될 수 있기 때문에, 동일한 이벤트 순서를 백업 영상과 시뮬레이션 화면으로도 준비했습니다. 핵심 흐름은 앱의 Find 명령이 Gateway와 옷걸이를 거쳐 LED와 ACK로 돌아오는 구조입니다.”

## 14. 실제 서비스·검증

### 화면

검증한 기능, 사용 후기, 향후 검증 항목을 구분해서 표시한다.

### 대본 — 실제 후기와 실물 검증이 충분한 경우

“다음으로 실제 서비스 관점에서 확인한 결과를 말씀드리겠습니다.”

“사용자들은 옷의 위치를 직접 기억하지 않아도 앱에서 옷의 목록과 상태를 확인할 수 있었고, 찾기 기능을 통해 해당 옷걸이를 빠르게 구분할 수 있었습니다.”

“특히 기존 옷장 사용 습관을 바꾸지 않고, 옷을 걸고 빼는 행동만으로 정보가 갱신된다는 점에서 사용성이 있다고 판단했습니다.”

“앞으로는 `[실제 사용자 수]`명의 사용자 피드백과 `[실제 측정 항목]`을 바탕으로 인식 거리, 전원 안정성, 통신 지연 시간을 더 정밀하게 검증할 예정입니다.”

### 대본 — 아직 실물 검증과 후기가 충분하지 않은 경우

“현재 프로토타입 단계에서 저희가 확인한 범위는 UID 등록, 옷과 옷걸이 상태 모델, 실시간 웹 업데이트, Find 명령과 ACK 흐름입니다.”

“반면 PN532 실물 인식 거리, 금속 옷봉에서의 NFC 간섭, 포고 전원 안정성, 장시간 동작은 실제 하드웨어 시험을 통해 추가로 검증해야 합니다.”

“저희는 검증된 기능과 앞으로 검증할 항목을 구분해서, 실제 서비스로 발전할 수 있는 프로토타입을 만들고 있습니다.”
